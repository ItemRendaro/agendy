# WWDC 2025で発表されたiOSアプリアイコンとXcode 26の変更点

iOS 26ではアプリアイコンにLiquid Glassの表現が加わり、作り方の選択肢が増えた。 レイヤー型のアイコンが推奨されるが、従来どおり1024×1024pxのフラットなPNGでも提出できる。

# iOSアプリアイコンの要件を観点ごとに整理する

AppleのHuman Interface Guidelinesの内容を、観点ごとに表にした。 各項目の詳細は後の節で説明する。

観点 要点
デザイン構成 レイヤー型が推奨。フラットPNGでも提出できる
システム効果 Liquid Glassによる光・奥行き・動きが自動で適用される
Icon Composer 使用は任意。Xcodeに取り込める
審査条件 PNG形式・不透明・1024px・角丸非指定・HIG準拠が基本要件
外観対応 明／暗／ティントなどの切り替えに対応できる（任意）
代替アイコン 利用できる。全バリアントが審査対象

アプリアイコンは、ホーム画面、検索結果、通知、システム設定、共有シートなどに表示される。 ユーザーとの最初の接点として、アプリの目的・性格・ブランドを端的に伝えるよう設計する。

  • App icons | Apple Developer Documentation (opens new window)

# アイコンは背景と前景のレイヤーで構成できる

iOSのアイコンは、背景レイヤーと複数の前景レイヤーで構成できる。 レイヤーを使うと、奥行き・立体感・動的な視覚効果が得られる。 レイヤーを使わず、従来どおりフラットなPNG画像だけを提出することもできる。

# iOS 26からLiquid Glassの視覚効果が自動で適用される

iOS 26から、アイコンに次の動的な視覚効果が適用される。

  • スペキュラハイライト（光沢感）
  • フロスト感（すりガラス状のぼかし）
  • 半透明・透過表現
  • デバイスの動きに応じた視覚変化

# Icon Composerは推奨されるが必須ではない

Xcode付属のIcon Composerを使うと、レイヤーアイコンを作成・調整できる。 主な機能は次のとおりである。

  • レイヤーの位置と透過の調整
  • 外観バリエーション（デフォルト、ダーク、クリア、ティント）ごとの表示確認
  • エクスポートしてXcodeのAsset Catalogに登録

Icon Composerの使用は推奨されるが、必須ではない。 既定の形式・サイズ・品質を満たすPNGであれば、他のツールで作ったアイコンでも問題ない。

# 1024px正方形で作り、文字と写真は避ける

項目 ルール
形状 1024×1024pxの正方形画像を提出する。角丸マスクはiOSが自動で適用する
テキスト 原則非推奨。可読性と多言語対応に欠けるため、必要な場合を除いて避ける
写真・UI 非推奨。縮小表示に向かないため、抽象的なイラストで表現する
Apple製品の再現 商標権上の理由で禁止

# 外観スタイルごとのアイコンは用意しなくても自動生成される

iOS 16以降、ユーザーは次の外観スタイルを選択できる。

  • デフォルト
  • ダーク
  • クリア（明／暗）
  • ティント（明／暗）

アプリはこれらに対応するアイコンを用意できるが、任意である。 用意しない場合は、システムが自動で生成する。

筆者の考えでは、レイヤー構造で作っておくと外観の切り替えにも対応しやすい。 視認性とブランドの一貫性を保ちやすいためである。

# 代替アイコンもすべて審査対象になる

iOSは、ユーザーが設定画面からアイコンを切り替える機能に対応している。 例えば、スポーツチームごとのアイコンや季節限定のアイコンである。 代替アイコンもすべて審査対象になる。 通常のアイコンと同様に、ダーク版とティント版を含める必要がある。

# App Intentがビジュアルインテリジェンスに対応した

App Intentは、アプリのアクションとコンテンツをシステム全体に統合する仕組みである。 統合先は、Siri、Spotlight、ウィジェット、コントロールなどである。 今回、ビジュアルインテリジェンスへの対応が加わった。 アプリはビジュアル検索結果を提供でき、ユーザーはその結果からアプリに直接移動できる。

例えばEtsyは、ビジュアルインテリジェンスで商品を速く見つけられるようにしている。 これによりiOSアプリのユーザー体験を強化している。

# Swift 6.2はWebAssemblyに対応した

Swift 6.2は、パフォーマンスと並行性を強化する。 C++、Java、JavaScriptなど、ほかの言語との相互運用性も強化する。 オープンソースコミュニティとの協力により、WebAssemblyに対応した。

Swift 6のStrict Concurrencyチェックを基盤に、シングルスレッドのコードの記述も簡素化される。 モジュールやファイル単位で、デフォルトでメインアクターで動作するよう構成できる。 これにより追加の注釈が不要になる。

# ContainerizationフレームワークでLinuxコンテナをMacで実行できる

Containerizationフレームワークを使うと、MacでLinuxコンテナイメージを作成、ダウンロード、実行できる。 Appleシリコン向けに最適化されたオープンソースフレームワーク上に構築されている。 コンテナイメージ間は安全に分離される。
